# Stress test, 2026-10-21 (round 1)

Round 1 ran real noScribe CLI transcriptions with `--live-feed` while headless Chromium watched the viewer. Results are not in the repo; the test tools are in `live/stress/`.

## Setup

- Machine: NVIDIA GeForce RTX 5060 Ti (shared GPU). Container RAM limit 10 → 20 GiB.
- noScribe CLI from the host venv (`/home/cheng/noScribe/venv`), run with `--live-feed live/feeds/`.
- Model breeze-asr-25 unless noted. Speaker detection `auto`, `--timestamps`.
- One transcription at a time. Runs are guarded: at least 4 GiB of GPU memory free, and no other GPU compute process.

## Methodology

Tools in `live/stress/`:

- `run_real.sh`: guarded real run. Records wall time and peak RSS of the process tree, and writes `result.json`.
- `recorder.py`: headless Chromium via Playwright. It wraps `EventSource` before the app loads. Per-segment latency is the browser receive time minus the CLI's `t` in the feed line (same machine clock). Long tasks come from a `PerformanceObserver`. FPS comes from `requestAnimationFrame`, counted per second. Screenshots are taken at 1440 and 390 px.
- `demo_driver.sh`: keeps the viewer busy for demos, alternating real runs (when the GPU and memory allow) with replays of finished feeds.
- `test_reconnect.py` (round 2): kills and restarts the viewer server during a replayed run, then checks the reconnecting state and that no segment is duplicated.

RTF is wall time divided by audio length. Wall time includes the ~20 s model load and diarization, so short clips have a high RTF.

Test audio is built by `live/samples/stress/build-stress-set.sh`. Sources and licences are in `live/samples/stress/SOURCES.md`. Several clips are synthetic splices: 03 (multi-speaker), 04 (code-switching) and 05 (noisy). 02 is Mandarin, but its accent is not verified as Taiwanese.

## Bugs found in round 1 and their fixes

- A killed run showed "running" for 30 min. Fixed on the server with a pid liveness check and a status watcher (commit `545417b`).
- The UI ignored `stale` from `runs` messages. Fixed in `b3954fa`.
- Cloudflare quick tunnels buffer SSE (HTTP 200, 0 bytes after 25 s). Switched to localhost.run (`5075615`).

Round 2 (this branch) addresses: following the newest live run; Live badge and elapsed-time semantics; end-state messages and humanised errors; output basename; 404/422 handling for peaks; reconnect state and dedupe.

## Leftover issues in the noScribe CLI

Not changed here. The CLI must behave as before when the feed is off.

1. **Orphaned diarization child on `kill -9`.** Killing the CLI with SIGKILL during diarization leaves the multiprocessing child (`multiprocessing.spawn … --multiprocessing-fork`, PPID 1) alive, with about 1.5 GB RSS and about 130 MiB of GPU memory. It blocks the next run's GPU check until it is killed by hand. Repro: start a run on a clip of 3 min or longer, run `kill -9 <cli pid>` about 35 s in, then check `nvidia-smi --query-compute-apps=pid --format=csv` and `ps -o pid,ppid,cmd -p <pid>`.
2. **Random-bytes input gives the wrong error.** `noScribe --no-gui … 90-corrupt.mp3 out.html` fails with `Error in step 1 - converting the audio.: tuple index out of range` instead of a decode error. Truncated and empty files get ffmpeg's `Invalid data found when processing input`. The viewer humanises both.

## How to reproduce

Run from the repo root.

```sh
# Build the test audio (media files are git-ignored)
live/samples/stress/build-stress-set.sh

# One guarded real run: wall time, peak RSS, result.json
live/stress/run_real.sh live/samples/stress/03-multi-speaker.mp3 /tmp/out

# Page opened 35 s into the run
RECORDER_ARGS="--join-after 35" live/stress/run_real.sh live/samples/stress/04-codeswitch-zh-en.mp3 /tmp/out-04

# Other model
MODEL=breeze-asr-26 live/stress/run_real.sh live/samples/stress/02-zh-tw-speech.mp3 /tmp/out-02-26

# Feed off (the CLI behaves as before)
LIVE_FEED=off live/stress/run_real.sh live/samples/stress/09-format.m4a /tmp/out-09-off
```

Results are appended to `live/stress/results/results.tsv` (git-ignored).
